## 1. 目标与范围

### 1.1 目标

在标注界面提供 **「模型划分子任务」** 一键能力：把当前完整轨迹交给模型，按操作意图生成整套 `sub_tasks`（边界 + 每段 `instruction`），并支持 **撤销** 回到划分前的人工/旧结果。

### 1.2 本阶段做 / 不做

| 做 | 不做（后续另议） |
|---|---|
| 用户手动点「一键划分」 | 上传后云端**自动**划分子任务 |
| **整轨覆盖**当前 `sub_tasks` | 只切未锁定段 / 只填空意图（策略 B 细化） |
| 划分前备份，支持 **撤销一次**（可扩展为多层） | 本地一键填写逐步「操作意图」「操作结果」（逐步标注仍走云端现有能力） |
| 文本动作摘要切分（可带截图路径便于追溯） | 首版多模态看图像素切分 |

### 1.3 与功能一的关系

| 功能一（已有） | 功能二（本文） |
|---|---|
| 人在标注页拆分 / 合并 / 填子任务意图 | 模型一键生成整套子任务 |
| 主流程：整段录完再标注划分；无浮窗录中切分 | 不依赖浮窗；在标注页触发 |
| 数据：`sub_tasks` + `sub_task_metadata` | **复用同一 schema**，`source=model` |

## 2. 已确认产品决策

| # | 决策 |
|---|---|
| 1 | 一键划分 = **一律整轨覆盖** 当前 `sub_tasks` |
| 2 | 必须提供 **撤销**（恢复划分前的 `sub_tasks`） |
| 3 | 本阶段以 **一键手动触发** 为主；上传后自动跑延后 |
| 4 | 切分输入优先：动作序列摘要 + 逐步已有 `step_instruction` / `intent`（有则带上）；摘要可带 step 索引与截图相对路径，首版不强制送图像 |
| 5 | 子任务字段与功能一一致：`id` / `index` / `instruction` / `start_step` / `end_step` / `source` / `model` / `prompt_version`；`confidence` / `needs_review` 模型写出、人工可改 |
| 6 | 模型结果：`source=model`；撤销后恢复备份中的原 `source` |

### 2.1 与「部分人工划分 / 锁定」的关系（延后）

此前讨论过策略 B（instruction 非空锁定、系统默认单段才整轨切等）。  
**一键整轨覆盖阶段不启用这些规则**：用户点一键即表示接受整轨重划；不满意用撤销。  
上传自动跑 + 锁定策略作为功能二增强版另开文档/迭代。

### 2.2 与逐步「操作意图 / 操作结果」的关系（现状说明）

| 能力 | 现状 |
|---|---|
| 逐步「操作意图」「操作结果」等 | 由云端 Qwen **逐步标注**写入；需上传或「重新标注」后，再「加载云端会话」查看 |
| 本地仅打开录制目录标注 | **不能**一键让模型填这些逐步字段 |
| 本功能「一键划分子任务」 | 只生成 / 覆盖 **子任务层** `sub_tasks`，不替代逐步标注 |

若轨迹尚无逐步说明，一键划分仍应可运行（仅用 action 序列）；有逐步说明时质量通常更好。产品上可提示：「建议先完成云端逐步标注再划分子任务」，但不作为硬性拦截（除非实现时另定）。

## 3. 用户操作流程

```text
打开标注页（本地目录 或 云端回流会话）
  → （可选）已有人工 sub_tasks / 或系统默认单段
  → 点击「模型划分子任务」
  → UI 进入进行中状态（禁用重复点击）
  → 后端调用划分模型
  → 成功：旧 sub_tasks 写入备份；界面展示新分段
  → 用户审阅：可改 instruction、再手拆/合并、改 needs_review
  → 若不满意：点「撤销模型划分」→ 恢复备份
  → 保存（本地 trajectory.json；若云端会话则一并 reviewed）
```

### 3.1 按钮与状态（标注页）

| 控件 | 行为 |
|---|---|
| **模型划分子任务** | 触发整轨划分；进行中 disabled；失败 toast/状态行报错且不覆盖 |
| **撤销模型划分** | 仅当存在可用备份（`previous_sub_tasks != null`）时启用；恢复后清空备份或标记已撤销 |
| 原有拆分 / 合并 / 编辑 | 划分后仍可用；人改边界后建议将对应段 `source` 改为 `hybrid`（推荐，非首版阻塞） |

## 4. 数据约定

### 4.1 覆盖与备份

一键成功时：

```json
{
  "sub_tasks": [ /* 模型新结果 */ ],
  "sub_task_metadata": {
    "status": "completed",
    "splitter": "qwen_subtask_v1",
    "manual_boundary_count": 0,
    "split_at_unix": 1710000000.0,
    "prompt_version": "subtask-split-v1",
    "previous_sub_tasks": [ /* 划分前的完整 sub_tasks 数组 */ ]
  }
}
```

说明：

- `previous_sub_tasks`：撤销用；一键前若已有备份，**本版策略**为再次一键前用当前 `sub_tasks` 覆盖备份（只保留「上一次」），或先提示「将覆盖可撤销的上一版」——实现时采用 **只保留一层上一次** 即可。  
- `manual_boundary_count`：模型整轨覆盖后置 `0`（表示当前边界非人工打点计数）；撤销后应一并恢复旧 metadata 中的 count（见下）。

**更稳妥的备份（推荐实现）：** 备份整份 `sub_task_metadata` 中与分段相关的快照，或同时备份：

```json
"previous_snapshot": {
  "sub_tasks": [ ... ],
  "sub_task_metadata": { ... }  // 不含 previous_* 自身，避免嵌套过大
}
```

撤销 = 用 snapshot 写回 `sub_tasks` + metadata（清除 snapshot）。

### 4.2 模型产出的单条 sub_task

```json
{
  "id": "st_...",
  "index": 0,
  "instruction": "打开设置并滚动到隐私项",
  "start_step": 0,
  "end_step": 3,
  "source": "model",
  "confidence": 0.82,
  "needs_review": false,
  "model": "Qwen3.6-27B",
  "prompt_version": "subtask-split-v1"
}
```

服务端校验（复用 `subtask_schema.validate_sub_tasks`）：

- 连续、不重叠  
- 覆盖全部非 `terminate` 步骤  
- `instruction` 非空（模型必须给出；失败则整次一键失败不覆盖）  
- `confidence` ∈ [0,1]；低于阈值（如 0.7）可设 `needs_review=true`

### 4.3 撤销后

- `sub_tasks` / 相关 metadata 恢复为备份  
- 清除 `previous_sub_tasks` / `previous_snapshot`  
- UI 刷新分组列表

## 5. 模型调用设计

### 5.1 模块

新建例如 `ducktrack/subtask_splitter.py`（与 `qwen_annotator.py` 逐步标注分离）：

- 环境变量可与逐步标注共用：`DUCKTRACK_QWEN_URL` / `TOKEN` / `MODEL`，或独立 `DUCKTRACK_SUBTASK_*`  
- `prompt_version`：如 `subtask-split-v1`  
- 原始响应当落盘：`model_responses/subtask_split.json`（便于排错）

### 5.2 输入摘要（示例）

```json
{
  "query": "",
  "steps": [
    {
      "index": 0,
      "action": "click",
      "step_instruction": "...",
      "intent": "...",
      "before": "frames/event_000000_before.webp"
    }
  ]
}
```

不含 `terminate`。坐标等可精简，避免 prompt 过长。

### 5.3 输出约束（Prompt 要点）

- 只输出 JSON 数组：`[{ "start_step", "end_step", "instruction", "confidence" }, ...]`  
- 必须覆盖 `[0, last_actionable]`，不重叠、无空段  
- 按**操作意图变化**切分，避免「一步一段」  
- 不编造逐步截图里看不见的科学结论  

服务端为每条补全 `id` / `index` / `source=model` / `model` / `prompt_version` / `needs_review`。

### 5.4 触发位置（推荐）

| 层级 | 建议 |
|---|---|
| **云端** | `POST /api/v1/sessions/{session_id}/split_subtasks`：对会话目录内 trajectory（优先 reviewed > annotated > raw）执行划分，写回并可返回最新 JSON |
| **本地 annotator** | 若当前是云端会话：调上述云端 API，再刷新本地缓存；若纯本地目录：可调本地后端 API，由本地后端转发到同一 Qwen URL（需配置），或提示「请先加载云端会话」 |

**首版推荐路径（实现简单、与现网一致）：**

1. 用户通过云端回流打开会话（或本地已有上传对应的 session）  
2. 一键 → 云端 splitter → 写回 `trajectory.annotated.json` 或 `trajectory.reviewed.json`（规则与保存策略对齐）  
3. 客户端拉取/应用结果到当前 `trajectoryData`

纯本地未配置模型 URL 时：按钮可点但返回明确错误「未配置划分模型」。

本地已有占位：`POST /api/recordings/{name}/split_subtasks` → 501，实现时改为真正调用 splitter。

## 7. 验收标准

- [ ] 标注页可点击「模型划分子任务」，成功后侧栏变为模型分段且含非空 `instruction`  
- [ ] `source` 均为 `model`（新结果），含 `model` / `prompt_version`  
- [ ] 划分前已有人工多段时，一键后被整轨替换；点撤销可恢复人工多段  
- [ ] 模型失败 / 校验失败：界面报错，磁盘与内存中的旧 `sub_tasks` 不变  
- [ ] 覆盖完整、无重叠、不含 terminate  
- [ ] 保存后再加载，分段与撤销备份行为符合约定（撤销后保存则备份清除）  
- [ ] 未配置模型时有清晰错误，不静默失败
