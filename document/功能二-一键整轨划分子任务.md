## 1. 目标与范围（v1 基线，仍适用）

### 1.1 目标

在标注界面提供 **「模型划分子任务」** 一键能力：把当前完整轨迹交给模型，按操作意图生成整套 `sub_tasks`（边界 + 每段 `instruction`），并支持 **撤销** 回到划分前的人工/旧结果。

### 1.2 v1 做 / 不做

| 做（v1） | 不做（v1 已明确延后；部分归入 v2） |
|---|---|
| 用户手动点「一键划分」 | 上传后云端**自动**划分子任务 |
| **整轨覆盖**当前 `sub_tasks` | 只切未锁定段 / 只填空意图（策略 B） |
| 划分前备份，支持 **撤销一次** | 本地一键填写逐步「操作意图」「操作结果」 |
| 文本动作摘要切分 | ~~首版多模态看图像素切分~~ → **改由 v2 交付** |

### 1.3 与功能一的关系

| 功能一（已有） | 功能二 |
|---|---|
| 人在标注页拆分 / 合并 / 填子任务意图 | 模型一键生成整套子任务 |
| 主流程：整段录完再标注划分；无浮窗录中切分 | 不依赖浮窗；在标注页触发 |
| 数据：`sub_tasks` + `sub_task_metadata` | **复用同一 schema**，`source=model` |

## 2. 已确认产品决策（v1 + 延续到 v2）

| # | 决策 |
|---|---|
| 1 | 一键划分 = **一律整轨覆盖** 当前 `sub_tasks` |
| 2 | 必须提供 **撤销**（恢复划分前的 `sub_tasks`） |
| 3 | 本阶段以 **一键手动触发** 为主；上传后自动跑延后 |
| 4 | **v1 输入**：动作序列摘要 + 逐步已有说明（有则带上）；路径可附带但不等于看图 |
| 4b | **v2 输入**：同上摘要 + **最多 12 张关键帧图像**；证据优先级以截图内容写意图、以动作定序和范围 |
| 5 | 子任务字段与功能一一致；`confidence` / `needs_review` 模型写出、人工可改 |
| 6 | 模型结果：`source=model`；撤销后恢复备份中的原 `source` |
| 7 | **v2 模型**：SiliconFlow `Qwen/Qwen3-VL-32B-Instruct`（可用 `DUCKTRACK_SUBTASK_MODEL` 单独指定，与逐步标注文本模型解耦） |

### 2.1 与「部分人工划分 / 锁定」的关系（延后）

一键整轨覆盖阶段不启用锁定规则；不满意用撤销。上传自动跑 + 锁定策略另议。

### 2.2 与逐步「操作意图 / 操作结果」的关系

| 能力 | 现状 |
|---|---|
| 逐步「操作意图」「操作结果」等 | 由云端 Qwen **逐步标注**写入（`qwen_annotator`，可看图，与功能二不同链路） |
| 本功能「一键划分子任务」 | 只生成 / 覆盖 **子任务层** `sub_tasks`；**边界与子任务意图在同一次调用中产出** |

## 3. 用户操作流程（v1 / v2 交互不变）

```text
打开标注页 → 点击「模型划分子任务」→ 后端调用划分模型
  → 成功：备份旧结果并展示新分段 → 可撤销 / 手改 → 保存
```

按钮行为同前：进行中禁用；失败不覆盖；存在备份时可「撤销模型划分」。

## 4. 数据约定（v1 / v2 共用 schema）

### 4.1 覆盖与备份

一键成功时写入 `sub_tasks` + `sub_task_metadata`（含 `previous_sub_tasks` / `previous_snapshot`）。  
v1 示例字段：`splitter=qwen_subtask_v1`，`prompt_version=subtask-split-v1`。  
v2 成功后拟为：`splitter=qwen_subtask_v2`，`prompt_version=subtask-split-v2`，`model=Qwen/Qwen3-VL-32B-Instruct`（以实际 env 为准）。

### 4.2 模型产出单条 / 校验

与功能一相同字段；须连续覆盖全部非 `terminate` 步；`instruction` 非空；`confidence`∈[0,1]。

### 4.3 撤销

用 snapshot 写回并清除备份。

## 11. 提示词全文（已确认）

### 11.1 v1 现行 Prompt（`subtask-split-v1`，线上正在使用）

**System：**

```text
You are a Windows GUI trajectory sub-task segmentation model.
Given an ordered list of atomic GUI actions (and optional per-step instructions/intents),
split the trajectory into contiguous sub-tasks. Each sub-task represents one user intent /
operation goal (not one atomic click).

Rules:
1. Return ONLY a JSON array, no markdown or extra text.
2. Each item: {"start_step": int, "end_step": int, "instruction": string, "confidence": number}
3. instruction must be a non-empty concise Chinese or English intent description.
4. confidence is in [0, 1].
5. Ranges are inclusive, contiguous, non-overlapping, and must cover every step index from 0
   through last_step_index (provided in the user message). No gaps, no empty segments.
6. Prefer fewer meaningful intent segments over one-step-per-segment.
7. Do not invent scientific outcomes; describe GUI operation intent only.

Example:
[
  {"start_step": 0, "end_step": 2, "instruction": "打开面板并拖到目标区域", "confidence": 0.86},
  {"start_step": 3, "end_step": 5, "instruction": "滚动浏览列表", "confidence": 0.8}
]
```

**User（模板）：**

```text
last_step_index={last}
Split the following trajectory into sub-tasks.
{摘要JSON}
```

**重试 User：**

```text
Previous response was invalid. Return ONLY a JSON array covering 0..{last} with non-empty instructions.
```

> 子任务**意图**即返回项中的 `instruction`，与边界在同一次调用中完成，无第二次「只填意图」请求。

### 11.2 v2 拟用 Prompt（`subtask-split-v2`，**已确认文案，待编码接入**）

**System：**

```text
You are a Windows GUI trajectory sub-task segmentation model with vision.
You will receive:
(1) an ordered text summary of atomic GUI actions, and
(2) up to 12 keyframe screenshots, each labeled with its step index and action type.

Your job: split the trajectory into contiguous sub-tasks. Each sub-task is one user intent /
GUI operation goal (not one atomic click). Also write a clear instruction for each sub-task.

Evidence priority:
1. Screenshot content (window titles, buttons, menus, input fields, dialogs) is primary for writing instruction.
2. Action names/parameters define order and ranges; use them to decide start_step/end_step.
3. If text summary conflicts with what is visible in screenshots, trust the screenshots.
4. Screenshot path strings in JSON are NOT visual evidence; ignore paths; only provided images count.
5. If a span has no screenshot, infer cautiously from neighboring actions/images and lower confidence.

Rules:
1. Return ONLY a JSON array, no markdown or extra text.
2. Each item MUST be:
   {"start_step": int, "end_step": int, "instruction": string, "confidence": number}
3. instruction must be non-empty, concise, and concrete (Chinese preferred unless UI is English-only).
   Good: "在开始菜单中搜索并打开记事本"
   Bad: "执行后续界面操作" / "进行一些点击"
4. confidence is in [0, 1]. Lower confidence when images are missing or UI text is unreadable.
5. Ranges are inclusive, contiguous, non-overlapping, and MUST cover every index from 0 through
   last_step_index. No gaps, no empty segments. Do not include terminate-only trailing steps if
   last_step_index already excludes them.
6. Prefer fewer meaningful intent segments over one-step-per-segment.
7. Place boundaries where the user goal changes (e.g. switch app/window, finish typing and submit,
   open a new panel, start a different workflow).
8. Do not invent scientific outcomes or hidden system state; describe only GUI operation intent.

Example:
[
  {"start_step": 0, "end_step": 4, "instruction": "打开文件资源管理器并进入目标文件夹", "confidence": 0.88},
  {"start_step": 5, "end_step": 9, "instruction": "在搜索框输入关键词并查看结果", "confidence": 0.84}
]
```

**User（拟用形态）：**

```text
last_step_index={last}
max_images={n}
Split the following trajectory into sub-tasks.
Use BOTH the JSON summary and the attached keyframe screenshots.
JSON summary:
{摘要JSON}

# 随后多段多模态 content：
# [text] Keyframe: step={k}, action={name}, role={boundary|representative}
# [image_url] <该步截图 data URL / 兼容网关格式>
```

输出 schema 与 v1 相同，便于校验与写回逻辑复用。

## 12. v2 方案：关键帧多模态看图切分

### 12.1 动机

v1 仅根据 `action` / 少量 `parameters` 推断，同为 `click` 无法区分点「保存」还是「关闭」，导致**边界与意图**不够准。v2 为模型提供真实界面证据。

### 12.2 为什么换 VL 模型

| 模型 | 角色 |
|---|---|
| `Qwen/Qwen3.6-27B` | **文本**模型；适合 v1；即使用同一 API 网关，也不是为 GUI 看图切分优化的 VL 产品 |
| `Qwen/Qwen3-VL-32B-Instruct` | **视觉语言** Instruct 模型；适合按 JSON 输出 + 读截图；**确认为 v2 划分模型** |

可选配置：划分用 `DUCKTRACK_SUBTASK_MODEL=Qwen/Qwen3-VL-32B-Instruct`；逐步标注仍可用原文本/其它模型，互不强制同一 `DUCKTRACK_QWEN_MODEL`。

若网关/模型不支持多图，应明确报错或回退 v1 纯文本切分（实现时二选一，推荐可配置）。

### 12.3 抽帧与上限（已确认）

- **整轨最多传 12 张图**（`DUCKTRACK_SUBTASK_MAX_IMAGES`，默认 12）  
- 优先 `settled`（无则 `before`）  
- 策略组合（实现时可微调）：  
  - **边界候选帧**：动作类型突变（如 type↔click）、输入段首尾等  
  - **代表帧**：均匀抽样补足上限  
- 每张图旁标注 `step_index`、`action`、`role`  
- 建议缩小边长（如最长边 ≤1024）控制费用与超时  

### 12.4 调用形态

```text
System: subtask-split-v2
User: 文本摘要 + ≤12 张 image_url
→ JSON 数组 → validate_sub_tasks → apply_model_sub_tasks
```

落盘调试：`model_responses/subtask_split.json`（含选用了哪些帧、模型名、prompt_version）。
