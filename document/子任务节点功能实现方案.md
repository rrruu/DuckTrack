# DuckTrack 子任务节点功能实现方案

> 文档版本：v1.0  
> 日期：2026-07-27  
> 范围：**本阶段重点实现功能一**；功能二仅预留，不实现模型调用。

---

## 1. 背景与目标

### 1.1 问题

当前一次录制得到的是**扁平、连续**的长轨迹（如：单击 → 拖拽 → 滚动 → …）。训练与标注往往需要按**操作意图**把长轨迹切成多段「子任务」。

### 1.2 两个功能（总览）

| 功能 | 描述 | 本阶段 |
|---|---|---|
| **功能一** | 前端采集支持分子任务节点：录制中人工打边界，标注页编辑意图与边界 | **实现** |
| **功能二** | 完整轨迹上传云端后，由后端模型自动划分子任务 | **不实现**，但数据模型与流水线钩子需预留 |

### 1.3 本阶段目标

1. 录制中可通过浮窗（及可选热键）标记「下一子任务」。
2. `events.jsonl` 写入与现网风格一致的 `sub_task_boundary` 事件（进 `wants_fresh`，新截三帧）。
3. 导出 `trajectory.json` 时写入完整 `sub_tasks` + `sub_task_metadata`。
4. 标注 UI 按子任务分组展示，支持填写 `instruction`、拆分/合并、删步后重算边界。
5. 字段与校验模块设计为功能二可直接复用。

---

## 2. 已确认决策汇总

| 编号 | 决策 |
|---|---|
| A | 有人工边界则默认保留；功能二将来支持一键「用模型重新划分」并可撤销（本阶段不做） |
| B | 功能二将来用动作序列摘要切分；摘要可携带 step 索引与截图路径；本阶段不涉及 |
| C | 功能二流水线：先逐步 Qwen 标注，再据 `step_instruction`/`intent` 切子任务 |
| D | 功能二触发：上传后云端自动跑（本阶段只留钩子） |
| E | 子任务字段见 §3.2；`confidence`/`needs_review` 由模型写出、人工可改（人工创建时给默认值） |
| F | 顶层 `query` = 整段总任务描述；现常为空；切分不强制依赖 |
| 边界事件 | 进 `wants_fresh`（与 `pause`/`resume` 一样新截三帧） |
| 元数据 | 增加 `sub_task_metadata.manual_boundary_count` |

## 3. 数据模型

### 3.1 `trajectory.json` 顶层结构

```json
{
  "query": "",
  "application": "<hostname>",
  "platform_type": "windows",
  "url": null,
  "sub_tasks": [],
  "sub_task_metadata": {
    "status": "manual_complete",
    "splitter": "manual",
    "manual_boundary_count": 2,
    "split_at_unix": null,
    "prompt_version": null,
    "previous_sub_tasks": null
  },
  "trajectory": []
}
```

#### `sub_task_metadata` 字段说明

| 字段 | 类型 | 功能一取值 | 功能二预留 |
|---|---|---|---|
| `status` | string | `none` / `manual_complete` | 另加 `completed` / `skipped_manual` / `failed` |
| `splitter` | string | `none` / `manual` | 另加如 `qwen_subtask_v1` |
| `manual_boundary_count` | int | 录制中点击「下一子任务」的次数 | `> 0` 时云端自动切分应跳过 |
| `split_at_unix` | number \| null | 功能一可为 `null` | 模型切分完成时间 |
| `prompt_version` | string \| null | `null` | 模型 prompt 版本 |
| `previous_sub_tasks` | array \| null | 恒为 `null` | 「模型重划可撤销」时备份旧列表 |

**人工边界判定（功能二将使用）：**

- `manual_boundary_count > 0` → 视为用户认真切过，自动切分跳过；
- `manual_boundary_count == 0` → 可视为未切（即便有隐式单段覆盖），允许自动切分。

### 3.2 单个 `sub_task` 对象

```json
{
  "id": "st_01HZX...",
  "index": 0,
  "instruction": "",
  "start_step": 0,
  "end_step": 2,
  "source": "manual",
  "confidence": null,
  "needs_review": true,
  "model": null,
  "prompt_version": null
}
```

| 字段 | 必要 | 说明 |
|---|---|---|
| `instruction` | 是 | 子任务意图描述；录中可空，标注页补全 |
| `start_step` | 是 | 含端点，指向 `trajectory[]` 下标 |
| `end_step` | 是 | 含端点；**不包含**末尾 `terminate` 步 |
| `id` | 是 | 稳定唯一 ID（如 ULID/UUID），便于删步后仍可引用 |
| `source` | 是 | `manual` \| `model` \| `hybrid`；功能一写 `manual` |
| `index` | 是 | 子任务顺序，从 0 起 |
| `model` | 是（可 null） | 功能一为 `null`；功能二填模型名 |
| `prompt_version` | 是（可 null） | 功能一为 `null` |
| `confidence` | 建议 | 功能一默认 `null`；模型写出后人工可改 |
| `needs_review` | 建议 | 功能一：`instruction` 为空时 `true`，已填可为 `false` |

#### 范围与覆盖约定

1. `start_step` / `end_step` 连续、不重叠。
2. 默认覆盖全部**非** `terminate` 步骤。
3. 末尾 `terminate` 为会话级结束标记，不计入任一子任务。
4. **未打点**：导出 **1 段**覆盖全部非 terminate 步骤，`manual_boundary_count = 0`，`splitter = "none"` 或 `"manual"` 且 count=0（推荐：`splitter="none"`, `status="none"`）。
5. **有打点**：`splitter="manual"`, `status="manual_complete"`, `manual_boundary_count = 打点次数`。

可选（非必须）：每个 step 冗余写入 `sub_task_id`；以 `sub_tasks` 的范围为权威来源，删步后重算。

### 3.3 `events.jsonl`：`sub_task_boundary` 事件

#### 设计原则

- 走现有 `_enqueue_event` → `_capture_step_artifacts` → 写盘路径。
- **公共信封**与现网一致。
- **私有字段**仅保留切分所需。
- **进入 `wants_fresh` 名单**（与 `pause`/`resume` 相同），为切分时刻新截 before / after / settled 三帧。
- **不**导出为 `trajectory` 中的操作步骤（与 `pause` 类似，仅作控制/边界语义）。

#### 落盘示例

```json
{
  "time_stamp": 1982663.5792065,
  "action": "sub_task_boundary",
  "sub_task_id": "st_01HZX...",
  "sub_task_index": 1,
  "instruction": "",
  "frames": {
    "before": "frames/event_000012_before.webp",
    "after": "frames/event_000012_after.webp",
    "settled": "frames/event_000012_settled.webp"
  },
  "observation": "frames/event_000012_before.webp",
  "objects": "frames/event_000012_before.webp"
}
```

| 部分 | 字段 |
|---|---|
| 公共 | `time_stamp`, `action`, `observation`, `objects`, `frames`（因 wants_fresh） |
| 私有 | `sub_task_id`, `sub_task_index`, `instruction`（录中可空） |

说明：

- **不必**带 `button` / `name` / `x` / `y`——那些属于鼠标/键盘动作的私有字段。
- `sub_task_index`：新开启的子任务序号（0-based）；用户第一次点「下一子任务」时写入 index=1 的边界（表示从此刻起属于子任务 #1）。
- 开始录制时自动进入子任务 #0，**不强制**写首条 boundary。

#### `wants_fresh` 改动点

在 `ducktrack/recorder.py` 的 `_capture_step_artifacts` 中，将 `"sub_task_boundary"` 加入：

```python
wants_fresh = action in {
    "left_click",
    "right_click",
    "double_left_click",
    "double_right_click",
    "drag_start",
    "drag_end",
    "scroll",
    "pause",
    "resume",
    "sub_task_boundary",  # 新增
}
```

同时导出逻辑需**跳过**将该 action 聚合成 trajectory step。

### 3.4 边界 → 步骤下标映射规则

1. 按 `events.jsonl` 顺序扫描；正常动作仍按现有规则合并为 steps（drag/scroll/type 合并不变）。
2. 遇到 `sub_task_boundary`：关闭当前子任务（`end_step` = 已生成的最后一个 step 下标）；开启新子任务（`id`/`index` 取自事件；`start_step` = 下一个将生成的 step 下标）。
3. 若 boundary 紧挨在某次 drag 的 `drag_move` 中间（异常操作），仍按事件序切分；产品上引导用户在操作间隙点击。
4. 文件结束：闭合最后一段；附加 `terminate` 步仍不计入 `end_step`。

## 4. 功能一：实现方案（详细）

### 4.1 新建：`ducktrack/subtask_schema.py`

职责（功能一、二共用）：

- 工厂：`make_sub_task(...)`、`make_sub_task_metadata(...)`
- 校验：`validate_sub_tasks(steps, sub_tasks)`（覆盖、不重叠、范围、排除 terminate）
- 归一：`normalize_trajectory_subtasks(payload)`（旧数据缺字段时补默认，不报错）
- 维护：`rebuild_after_step_delete(...)`、`split_at_step(...)`、`merge_with_previous(...)`

保证所有写入路径字段集合一致，避免功能二再定义另一套 schema。

### 4.2 录制核心：`ducktrack/recorder.py`

| 改动 | 说明 |
|---|---|
| 状态字段 | `_current_sub_task_id`, `_sub_task_index`, `_manual_boundary_count` |
| 开始录制 | 生成子任务 #0 的 id；count=0 |
| `mark_sub_task_boundary(instruction="")` | index+=1；新 id；count+=1；`_enqueue_event({...}, important=True)` |
| `_capture_step_artifacts` | `sub_task_boundary` 加入 `wants_fresh` |
| `_export_trajectory_json` | 解析 boundary → `sub_tasks` + `sub_task_metadata`；无 boundary 则单段 + count=0 |
| 导出跳过 | boundary / pause / resume 等不进入操作 step 列表（保持现有 pause 行为，并扩展 boundary） |

### 4.3 本地 API：`ducktrack/server.py`

```http
POST /api/recordings/sub_task_boundary
Content-Type: application/json

{ "instruction": "" }

→ 200
{
  "ok": true,
  "sub_task_id": "st_...",
  "sub_task_index": 1,
  "manual_boundary_count": 1
}
```

录制状态接口（若已有）扩展返回：

```json
{
  "state": "recording",
  "sub_task_index": 1,
  "manual_boundary_count": 1
}
```

仅在 `recording`（非 paused 也可允许打点，建议：**paused 时仍允许打点**，或明确禁止——推荐允许，便于停顿时切意图）。

**预留（本阶段可返回 501）：**

```http
POST /api/recordings/{name}/split_subtasks
→ 501 not_implemented
```

### 4.4 Tauri 桥接：`tauri-annotator/src/backend_commands.rs`

- `backend_mark_sub_task_boundary({ instruction? })`
- `backend_get_recording_state` 透传 `sub_task_index` / `manual_boundary_count`
- （可选）全局热键 `Ctrl+Shift+N` → mark

在 `main.rs` 注册对应 command。

### 4.5 浮窗：`tauri-annotator/src/floating.ts`

录制中 UI：

- 状态行增加：`子任务 #N`（展示用 1-based：`sub_task_index + 1`）
- 按钮：**下一子任务** → 调用 mark API
- 保留：开始 / 暂停 / 停止 / 主窗口

失败时在状态行提示错误，不中断录制。

### 4.6 标注主界面：`tauri-annotator/src/App.vue`

| 能力 | 行为 |
|---|---|
| 加载兼容 | 无 `sub_tasks` 的旧目录：`normalize` 后可编辑或显示「未划分」 |
| 侧栏分组 | 按 `sub_tasks` 分组列出步骤；组标题显示 `instruction` 或「（未填写意图）」 |
| 编辑意图 | 修改当前子任务 `instruction`；非空时可设 `needs_review=false` |
| 拆分 | 「从此步起新子任务」→ 重算 id/index/start/end，`source=manual` |
| 合并 | 与上一段合并 |
| 删步 | 调用 schema 重建范围；禁止破坏校验时提示 |
| 保存 | 写回 `trajectory.json`，保留全部子任务字段 |
| 预留入口 | 「模型划分子任务」按钮 disabled，tooltip：「后续版本」 |

可选（低优先级）：顶层 `query` 编辑框，方便日后功能二。

### 4.7 云端预留：`ducktrack/cloud_server.py`

本阶段：

1. 确认 `save_reviewed` / 下载轨迹 **原样保留** `sub_tasks`、`sub_task_metadata`。
2. 在逐步标注成功后增加空钩子：

```python
def _maybe_split_subtasks(self, recording: Path) -> None:
    """Feature-2 placeholder: auto split after step annotation if manual_boundary_count == 0."""
    return
```

并在 `_annotate_with_qwen_locked` 写完 `trajectory.annotated.json` 之后调用（当前 no-op）。

### 4.8 明确不改（本阶段）

- `qwen_annotator.py` 逐步标注逻辑
- 上传 zip / `uploader.py` 核心逻辑
- 自适应截帧算法本身（仅扩展 wants_fresh 名单）

## 5. 功能二预留清单（不实现，仅约束）

| 预留项 | 用途 |
|---|---|
| 完整 `sub_task` / `sub_task_metadata` 字段 | 模型直接写同结构，`source=model` |
| `manual_boundary_count` | 自动切分跳过条件 |
| `previous_sub_tasks` | 一键重划后可撤销 |

| `_maybe_split_subtasks` | 挂接自动划分 |
| UI disabled 按钮 | 将来启用「重新划分」 |
| 本地 `split_subtasks` 501 | 或仅云端实现 |

功能二预期流水线（供对照，本阶段不开发）：

```text
上传 bundle
  → 逐步 Qwen 标注 → trajectory.annotated.json
  → 若 manual_boundary_count == 0：跑 splitter，写回 sub_tasks
  → 若 manual_boundary_count > 0：status=skipped_manual，保留人工 sub_tasks
```

## 7. 用户操作流程与产物

### 7.1 操作流程

```text
打开 Annotator / 浮窗
  → 选择保存目录，开始录制（自动进入子任务 #1）
  → 在目标软件中操作
  → 完成一个操作意图后，浮窗点击「下一子任务」（可选多次）
  → 继续下一意图的操作 …
  → 「停止并加载」
  → 标注页按子任务分组查看
  → 为每段填写 instruction（意图描述）
  → 可选：拆分 / 合并 / 删除误操作步骤
  → 保存
  → （可选）自动上传云端；云端本阶段仍只做逐步标注，不自动切子任务
```

### 7.2 目录产物

```text
recording-YYYY-MM-DD_HH-MM-SS/
  events.jsonl           # 含 sub_task_boundary（带 frames）
  frames/                # 含边界事件对应的三帧
  metadata.json
  trajectory.json        # 含 sub_tasks + sub_task_metadata
  upload_status.json
```
